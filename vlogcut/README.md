# vlogcut

長い旅行・ドライブ動画から「絵になる区間」だけを自動で抜き出して並べる CLI ツール。

音楽入れ・字幕入れ・色調整は編集ソフトでやる前提で、**その手前の「大量の素材から使えるところを探して切り出す」工程だけ**を自動化します。音声は常に捨てます。

```
2時間のドライブ動画  ->  vlogcut  ->  良さそうな 3〜5秒 × 30カット + 繋いだラフカット + EDL
```

## できること / できないこと

できること:

- 画としての良し悪し（ボケ・露出・色の豊かさ・コントラスト・手ブレ）を数値で判定して上位を採用
- シーンの切り替わりをまたぐ区間を避ける
- 同じ場所に固まらないよう、時間軸に散らして選ぶ
- 切り出したクリップ・繋いだラフカット・編集ソフトに戻すための EDL を書き出す

できないこと（人間か、後段の編集ソフトの仕事）:

- 「何が写っているか」の理解。犬が可愛いとか、この橋が旅のハイライトだ、といった判断はしません
- 音楽に合わせたリズム編集、テロップ、カラーグレーディング
- 手ブレ補正そのもの（ブレている区間を**避ける**だけ）

**採用結果は必ず `contactsheet.jpg` で目視確認してください。** 機械の判定はあくまで下選びです。

## インストール

Python 3.10 以降と ffmpeg が必要です。

```bash
pip install -r requirements.txt

# ffmpeg 本体（どれか一つ）
brew install ffmpeg          # macOS
sudo apt install ffmpeg      # Ubuntu / Debian
pip install imageio-ffmpeg   # 上記が使えない場合。Python から静的ビルドを取得する
```

`ffmpeg` が PATH に無い場合は環境変数で指定できます:

```bash
export FFMPEG=/path/to/ffmpeg
```

## 使い方

```bash
# フォルダごと投げる（サブフォルダも再帰的に探す）
python3 vlogcut.py ~/Videos/hokkaido -o out

# まず解析だけして、どこが採用されるか確認する（書き出さないので速い）
python3 vlogcut.py ~/Videos/hokkaido --dry-run

# 3分の Vlog を、1カット5秒で
python3 vlogcut.py ~/Videos/hokkaido -o out --total 180 --clip-len 5

# 0.5秒のクロスフェードで繋ぐ
python3 vlogcut.py ~/Videos/hokkaido -o out --xfade 0.5
```

最初は必ず `--dry-run` で当たりを付けてから本番を回すのがおすすめです。

## 出力されるもの

```
out/
├── clips/            採用した区間を1カット1ファイルで切り出したもの
├── roughcut.mp4      clips を時系列順に繋いだラフカット（音声なし）
├── edl.csv           元ファイル名 + イン点/アウト点。編集ソフトで組み直す用
├── edl.json          同上（スクリプトから扱う用）
└── contactsheet.jpg  採用カットの中間フレームを並べたサムネ一覧
```

想定ワークフロー:

1. `contactsheet.jpg` を眺めて、明らかに要らないカットを把握する
2. `clips/` をそのまま編集ソフトのタイムラインに放り込む（すでに軽くて短い）
3. 最終的な画質にこだわるなら、`edl.csv` のイン点/アウト点を見て元素材から組み直す

## 選び方の仕組み

1. **サンプリング** — 各動画を 192×108 / 秒2枚に落として ffmpeg から流し込む。フレームは1枚ずつ捨てるので、何時間の素材でもメモリ使用量は一定。
2. **フレームごとの採点**
   - ボケ … ラプラシアンの分散。**加点だけでなく乗算のゲート**にしているので、色や露出がどれだけ良くてもピンボケは上位に来ません
   - 露出 … 平均輝度が中庸か。白飛び・黒潰れは追加減点
   - 色の豊かさ … Hasler–Süsstrunk colorfulness。空・緑・夕焼けに反応します
   - コントラスト … 輝度の標準偏差。曇天のねむい画を下げます
3. **区間ごとの採点** — `--clip-len` 秒の窓をずらしながら、フレーム得点の平均から以下を減点
   - **手ブレ** … 窓内での動き量の**ばらつき**。「速いが滑らかなパン（良い）」と「細かく揺れる手持ち（悪い）」を区別するのが狙い
   - 品質のムラ … 窓の途中で画が変わるもの
   - 振り回し … 極端に速いパン
   - シーンの切り替わりをまたぐ窓は原則除外（`--allow-cuts` で許可）
4. **選択** — 得点順に貪欲に採用。同一ファイル内で `--min-gap` 秒以上離すので、良い場所に固まりません。

### 品質フロア

**目標尺に届かなくても、質の低い区間で埋めることはしません。** 最高得点の `--min-score-ratio` 倍（既定 0.75）を下回る区間は採用せず、代わりに「○秒しか採れませんでした」と報告します。素材の選別が目的なので、尺合わせのために微妙なカットを混ぜるのは逆効果だからです。

尺が足りないと言われたら、`--min-score-ratio` を下げる / `--min-gap` を小さくする / 素材を足す、のいずれかで調整してください。

## よく使うオプション

| オプション | 既定 | 説明 |
|---|---|---|
| `--total` | 120 | 仕上がりの目標尺（秒） |
| `--clip-len` | 4 | 1カットの長さ（秒） |
| `--min-gap` | 20 | 同一ファイル内でカット同士を離す秒数 |
| `--min-score-ratio` | 0.75 | 品質の足切り。0 で無効 |
| `--per-file-max` | 0 | 1ファイルからの最大カット数（0 = 無制限） |
| `--xfade` | 0 | クロスフェード秒数。0 でカット繋ぎ |
| `--height` / `--fps` | 1080 / 30 | 出力の解像度と fps |
| `--mode` | encode | `copy` にすると無劣化・高速だがキーフレーム単位の切り出しになる |
| `--sample-fps` | 2 | 解析の細かさ。上げると精度が上がり遅くなる |
| `--prefer-sharp` / `--prefer-color` | 0.30 / 0.25 | 採点の重み |
| `--dry-run` | — | 解析だけして採用予定を表示 |

全オプションは `python3 vlogcut.py --help` で確認できます。

## 素材別のおすすめ設定

```bash
# ドライブ（車載）: 景色が流れ続けるので長めのカット、間隔も広めに
python3 vlogcut.py drive/ -o out --clip-len 5 --min-gap 40 --total 180

# 街歩き・手持ち: ブレが多いので厳しめに絞る
python3 vlogcut.py walk/ -o out --clip-len 3 --min-score-ratio 0.85

# ドローン・三脚: ブレが無く全体が高品質なので足切りを緩める
python3 vlogcut.py drone/ -o out --clip-len 6 --min-score-ratio 0.6

# ファイル数が多く、どの日からも均等に拾いたい
python3 vlogcut.py trip/ -o out --per-file-max 3
```

## 速度とメモリ

4コアの Linux, 1080p30 / 16Mbps の素材での実測値:

| 項目 | 実測 |
|---|---|
| 解析速度 | 実時間の約 30 倍速（**1時間の素材で約2分**） |
| ピークメモリ | 約 31 MB（素材の長さ・解像度によらずほぼ一定） |

律速は ffmpeg のデコードです。そのため **`--sample-fps` を下げてもほとんど速くなりません**（1.0 / 2.0 / 4.0 で 2.0〜2.1秒と誤差の範囲でした）。ffmpeg は結局全フレームをデコードするためで、このオプションは速度ではなく**判定の細かさ**を調整するものだと考えてください。

書き出し（再エンコード）の方が解析よりずっと時間を食います。まず `--dry-run` で解析だけ回して採用結果に納得してから本番を回すのが、結果的に一番速いです。

## 注意点

- **`--mode copy` はキーフレーム単位** なので、イン点が指定より最大数秒ずれます。正確な位置が必要なら既定の `encode` を使ってください
- **`encode` は再エンコード**（既定 CRF 18）なので、わずかに劣化します。最終的な画質が重要なら `edl.csv` を使って元素材から組み直してください
- 縦動画や画角の違う素材が混ざっている場合、`--height` の 16:9 に**レターボックス**して揃えます
- 出力先が入力フォルダの中にあっても、自分の出力を素材として読み直すことはありません（出力先に `.vlogcut-output` という目印を置いています）
